# Source-Grounded Hierarchical Financial Analysis Thesis Design

> Status: Proposed for user and advisor review. This design does not replace the canonical specification until it is explicitly approved and recorded in `docs/DECISIONS.md`.

> Scope amendment: the canonical execution rule is now D-036. The five-bank/
> eight-quarter scope recorded below is retained as the provisional upper
> bound; the first baseline defaults to the 48-cell pilot.

## Goal

Deliver a defensible applied-fintech thesis prototype that tests whether a source-grounded hierarchical multi-agent workflow with bounded cross-level verification improves traceability, consistency, and anomaly explanation over a fair single-agent baseline on a fixed Vietnamese-bank dataset.

## Design decision in one sentence

Use the source-driven workflow as the data-governance foundation, use the
48-cell ACB/TCB/VPB pilot for the first empirical case, and make the comparison
between single-agent, hierarchical-without-critique, and hierarchical-with-
critique the thesis contribution. Retain five banks and eight quarters only as
a conditional expansion.

## Why this scope is necessary

The current staging snapshot is useful but not yet research-ready: it contains structured rows for 15 issuers and 43 annual-report PDFs, while all source records remain pending validation, TCBS has no usable structured coverage, official macro evidence is incomplete, and the provisional benchmark table contains invalid month-end dates. The thesis must therefore separate data readiness from agent implementation and must not treat retrieved vendor rows as validated financial truth.

The project is an applied thesis, not a production financial-advisory service. The prototype must demonstrate a useful and reproducible workflow, while the evaluation must remain able to show that the architecture is unnecessary or costly if it does not improve the selected outcomes.

## Research question

On the same frozen dataset, evidence policy, question set, model version, and output contract, does a hierarchical Macro/Sector/Company workflow with deterministic anomaly verification produce better factual correctness, evidence traceability, cross-level consistency, and anomaly explanation than a single-agent workflow, and what additional latency, model calls, and cost does it require?

## Claims the thesis may make

The thesis may claim that the evaluated prototype was designed, implemented, and measured on the defined case dataset; that the data pipeline preserves source identity and provenance; and that the measured comparison supports or rejects the value of the tested architecture within this case.

The thesis must not claim universal superiority of multi-agent systems, real-time financial advisory capability, complete coverage of Vietnamese listed financial institutions, investment returns, or that a retrieved vendor field is correct without source reconciliation.

## Original upper-bound scope

### Issuers

The primary benchmark contains five Vietnamese listed banks selected from the current high-coverage candidates: VCB, ACB, MBB, TCB, and VPB. The final selection is accepted only after official-source checks confirm that each selected issuer has the required statement packages and evidence for the benchmark metrics. The other staged issuers remain preserved as out-of-benchmark data and possible extension material.

### Periods

The benchmark contains eight fixed fiscal quarters from 2024_Q1 through 2025_Q4. A benchmark cutoff and publication-availability rule are recorded before gold-data construction. Calendar boundaries are generated by a date library and validated; impossible dates are rejected.

Quarter-only flow values are derived from Vietnamese YTD interim statements by subtracting the prior-quarter YTD value within the same fiscal year. Point-in-time balance-sheet observations preserve their reporting date. Annual and quarterly values are never silently mixed.

### Metrics

The primary bank metrics are NPL group 3-5, loan-loss-reserve coverage, CIR, and ROA or ROE using an explicitly chosen profit convention. NIM is included only after earning-asset mapping and source reconciliation pass the metric gate. CASA, LDR, and regulatory CAR are extension metrics unless their source-disclosed definitions and coverage pass the same gate.

Sector outputs are median, percentile, and period-over-period change computed only from accepted issuer observations. Macro context is limited to policy-rate movement, credit-growth context, and one or two additional indicators only when an authoritative period-aligned source is available.

### Sources

Official issuer filings or investor-relations documents, SBV publications, and GSO publications are primary evidence. Structured vendor APIs are ingestion accelerators and cross-checks until reconciled. Research reports are contextual material and may help discover candidate metrics or explanations, but never replace primary numeric evidence. Every accepted source record has URL, retrieval time, local path, content hash, publisher, source tier, license note, and validation status.

### Product behavior

The MVP runs locally from a frozen snapshot. It produces a company analysis, peer comparison, macro context, evidence appendix, quality flags, anomaly/verification log, and reproducible run record. A live crawler, intraday feed, investment execution, and public deployment are out of scope.

## Data foundation design

The existing staging databases and raw files are retained as immutable inputs. A new versioned gold snapshot is created after validation; it is never written over the staging database.

The accepted data path is:

```text
immutable raw retrievals
  → source registry and coverage manifest
  → normalized observations
  → deterministic derived metrics and peer benchmarks
  → validated evidence snippets
  → manually checked gold sample
  → experiment snapshot
```

The minimum accepted logical entities are:

- `SourceRecord`: identity, tier, URL, retrieval metadata, hash, license, and status.
- `MetricObservation`: ticker, sector, metric, value, unit, period, as-of date, source, locator, and quality status.
- `DerivedMetric`: formula version, input observation IDs, result, unit, period, and validation status.
- `EvidenceSnippet`: source, document, page or section, period, ticker, quote, and retrieval metadata.
- `GoldLabel`: checked value or evidence judgment, checker identity, check date, and resolution note.
- `CoverageSummary`: coverage by ticker, metric, period, source tier, and validation state.
- `ExperimentRun`: snapshot ID, question-set version, model configuration, prompt version, calls, latency, cost, and outputs.

The first gold snapshot must satisfy these gates:

- five selected banks and all eight benchmark periods are represented in the registry;
- required statement packages have at least 95% raw availability;
- primary metrics have at least 90% validated observation coverage or an explicit exclusion reason;
- every published numeric observation and qualitative claim has provenance;
- all formula tests cover normal, missing, zero-denominator, unit, and period-basis cases;
- critical and major source conflicts are resolved or excluded from the benchmark;
- a manually checked sample of at least 40 metric/evidence items is stored with check results.

The vector index is optional for the first runnable experiment. Metadata-filtered document retrieval is preferred until PDF text, table extraction, and page references are validated. Vector retrieval is added only if it is necessary for the evidence-retrieval comparison or materially improves a measured task.

## Agent architecture

### Deterministic data tools

Code owns source lookup, period and unit validation, metric calculation, peer statistics, coverage flags, and anomaly trigger evaluation. Tools return contract-valid payloads containing values, units, periods, source IDs, locators, and quality flags.

### Macro Agent

Retrieves accepted policy-rate, credit-growth, and macro evidence for the target period; it does not infer a causal effect from a single rate movement without evidence.

### Sector Agent

Retrieves accepted sector benchmarks and describes distribution and period changes; it does not recompute financial ratios from prose.

### Company Agent

Retrieves accepted company metrics and filing evidence, explains company-specific drivers, and preserves missing or conflicting values.

### Master Orchestrator

Creates a run configuration, dispatches the three specialists, validates payloads, runs deterministic anomaly triggers, requests at most two focused verification attempts, records every critique event, and synthesizes only valid payloads. Unresolved anomalies are reported explicitly.

The rules initially called contradiction rules are treated as anomaly or verification triggers. A trigger is not considered a true contradiction until an independent label says that the compared observations should be logically inconsistent under the metric definitions.

## Evaluation design

All systems receive the same question set, frozen snapshot, evidence policy, model version, and output schema.

### Arms

1. **Single-agent baseline:** one general financial-analysis agent using the same deterministic tools and evidence store.
2. **Hierarchical no-critique:** Macro, Sector, and Company specialists followed by synthesis without verification feedback.
3. **Hierarchical with critique:** the full bounded verification workflow.

The document-question-answering baseline is optional and may be included only as a descriptive lower-bound comparison; it is not a substitute for the fair tool-equivalent single-agent baseline.

### Primary outcomes

- factual correctness against the gold set;
- calculation correctness against deterministic expected values;
- evidence completeness and citation correctness;
- cross-level consistency;
- anomaly/verification precision and recall on independently labeled cases.

### Secondary outcomes

- end-to-end latency;
- model-call count;
- token or monetary cost;
- unresolved-conflict rate;
- failure rate and schema-validation rate.

Qualitative judgments use a fixed rubric and blind double review for a subset of outputs. Disagreements are retained rather than silently averaged away. The evaluation reports negative or null results as valid findings.

## Delivery sequence

### Gate 0: scope and decision freeze

Record the five-bank universe, eight-quarter cutoff, metric list, source hierarchy, TCBS treatment, and evaluation arms. Update the canonical specification only after review.

### Gate 1: data readiness

Repair period generation, validate selected source coverage, reconcile a representative bank sample, build normalized observations, compute derived metrics, validate evidence locators, and create the gold sample.

### Gate 2: parallel foundation build

While Gate 1 is being completed, implement and test schema validation, period/unit validators, metric calculators, query interfaces, coverage reporting, report contracts, and experiment instrumentation against fixtures. These components must not publish unvalidated financial conclusions.

### Gate 3: baseline

Run the single-agent baseline on the accepted snapshot and verify its run record, evidence traceability, and scoring pipeline.

### Gate 4: hierarchical system

Add specialists, orchestrator routing, anomaly triggers, bounded verification, and synthesis. Verify identical input snapshot and question set across arms.

### Gate 5: evaluation and thesis evidence

Run all arms, calculate primary and secondary outcomes, inspect failures, prepare thesis tables/figures, and document limitations and negative results.

## Failure and fallback policy

If a metric fails coverage or reconciliation, it is excluded or reported as missing; it is not zero-filled. If one selected bank fails the required-source gate, replace it only before the benchmark freeze and record the reason. If the critique arm does not improve primary outcomes after accounting for its extra calls, the thesis reports that the tested hierarchy was not justified for this case.

If official macro evidence cannot be collected for a metric, remove that metric from the primary evaluation rather than promote World Bank or DBnomics fallback data to authoritative status.
